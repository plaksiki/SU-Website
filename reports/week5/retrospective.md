# Sprint 3 Retrospective

## What Went Well
1. In backend we connected options, responses, and questions tables, added POST endpoints for admin actions.
   
2. In frontend we splitted Events and Departments into separate pages with fixed grid layout, built the admin panel with event and questionnaire creation, implemented the internship application questionnaire.

3. The team stayed in touch every day via chat in Telegram, which allowed us to quickly share updates without waiting for formal meetings.

4. The team completed all planned sprint tasks on time. All assignments task was splited between members and completed in time too.

5. We were able to find the right time to attend the meeting for both clients, also the clients provided the brand book.

## What Did Not Go Well
We determined that one backend developer was insufficient for this project, as it is difficult for a single person, working in this area for the first time, to meet deadlines. 

## What the team changed or attempted to change based on the previous Sprint Retrospective, and what results they observed
On the previous Sprint Retrospective, the team decided to clearly allocate tasks at the beginning of the sprint and account for each member's known unavailability (customer calls, trips) in advance, to avoid last-minute rushing before the deadline. This was successfully followed this sprint: tasks were allocated earlier, and the team observed noticeably less last-minute rushing compared to the previous sprint.


## Action Points

1. Reassign one frontend developer to support the backend team part-time to help meet deadlines, given that a single backend developer is not enough for the current scope.
2. Implement a dark mode for the site as a stretch goal, if time permits after core features are delivered.
